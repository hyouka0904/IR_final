# Week-1 MVP (Dense Retrieval + Evaluation) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Both tasks (semantic via CLIP, similar via DINOv2 / pHash) searchable from a script over a COCO gallery with FAISS Flat, and scored by an evaluation script — the README's "always ships" core.

**Architecture:** `src/` holds pure, tested modules (config, schema, preprocess, encoders, index, edits, metrics, trec, data, embed, pipeline, evaluate). `scripts/` are thin numbered CLIs over them. Evaluation and any later demo go through the same `src/pipeline.py` (`SearchEngine.search`). All parameters come from `configs/default.yaml`.

**Tech Stack:** Python 3.14 (`.venv`), torch (CPU wheel), open_clip_torch, timm (DINOv2), faiss-cpu, imagehash, Pillow, numpy, PyYAML, requests, pytest.

**Spec:** `README.md` (design), `team27_proposal.pdf` (one-page proposal). Scope for this plan was chosen by the user on 2026-11-20: "Week-1 core + eval", run on a small COCO slice (≈2,000 gallery / 200 + 200 queries), scale-up is a config change.

## Global Constraints

- "All parameters (models, K, fusion and feedback weights, index settings) live in `configs/default.yaml`, never hard-coded."
- "Evaluation scripts and the demo call the same `src/pipeline.py`."
- "`src/schema.py` fixes the data passed between the two members' modules."
- "Latency is recorded in three stages, with search always on CPU." Stages: `embed`, `search`, `rerank` (rerank is a no-op this week but timed).
- "No model is trained or fine-tuned." Pre-trained weights only.
- Gallery = subset of MS-COCO train2017; semantic queries = val2017 images (none in gallery).
- Semantic graded relevance = share of the query's COCO categories that the result also has.
- Similar queries = gallery images with synthetic edits: crop, rotation, color shift, JPEG, blur; ground truth = the original.
- Metrics: semantic nDCG@10, mAP; similar Recall@1, Recall@10, MRR per edit type. Runs written in TREC format.
- pHash is 64-bit, compared by Hamming distance.
- `data/`, `cache/` not in git. Images are not redistributed.
- Out of scope this plan: tags/BM25/RRF, Rocchio, alpha-QE, MMR, SigLIP, IVF-PQ/HNSW/cluster pruning, web demo, INRIA Holidays, ROxford.

## Review Focus

1. Query photos with EXIF orientation, RGBA/P/L/CMYK modes → upright RGB before encoding (Task 3 test).
2. `k` larger than the gallery → return only real results, never FAISS `-1` ids (Task 3 test).
3. Crop box outside the image or empty → clamped to image bounds; zero-area raises `ValueError` (Task 3 test).
4. Semantic query whose categories match nothing in the gallery → skipped from means and counted, like trec_eval skips queries without judgments (Task 2 + Task 8 tests).
5. Image downloads that fail or are interrupted → failure logged and skipped; rerun does not refetch existing files (Task 6 test).

### Task 2: Metrics and TREC files

**Files:** Create `src/metrics.py`, `src/trec.py`; Test `tests/test_metrics.py`

**Interfaces:**
- Produces (all on numpy arrays / lists):
  - `semantic_gains(query_cats: set[int], gallery_cats: list[set[int]]) -> np.ndarray` — gain_i = |q ∩ g_i| / |q|; zeros if q empty.
  - `ndcg_at_k(ranked_gains: Sequence[float], all_gains: Sequence[float], k: int) -> float` — DCG = Σ gain/log2(rank+1); ideal from top-k of `all_gains` sorted desc; returns `nan` if ideal DCG is 0.
  - `average_precision(ranked_rel: Sequence[bool], n_relevant: int) -> float` — Σ precision@hit / n_relevant; `nan` if n_relevant == 0.
  - `recall_at_k(ranked_ids, target_id, k) -> float` (1.0/0.0), `reciprocal_rank(ranked_ids, target_id) -> float` (0.0 if absent).
  - `mean_ignore_nan(values) -> tuple[float, int]` — (mean over finite values, count skipped).
  - `trec.write_run(path, rows: Iterable[tuple[str, int, int, float]], tag: str)` rows=(qid, docid, rank, score) → `qid Q0 docid rank score tag`; `trec.write_qrels(path, rows: Iterable[tuple[str, int, int]])` → `qid 0 docid grade`.

- [ ] Step 1: tests — `test_semantic_gains_share_of_query_categories` (q={1,2}, g=[{1},{1,2,3},{4}] → [0.5,1.0,0.0]); `test_ndcg_perfect_is_one`; `test_ndcg_known_value` (ranked [0,1], all [1,0], k=2 → 1/log2(3)); `test_ndcg_no_relevant_is_nan`; `test_ap_known_value` ([T,F,T], R=3 → (1+2/3)/3); `test_ap_zero_relevant_nan`; `test_recall_and_rr`; `test_mean_ignore_nan_counts_skipped`; `test_write_run_format` (exact line `q1 Q0 42 1 0.900000 clip`).

### Task 3: Preprocess and FAISS Flat index

**Files:** Create `src/preprocess.py`, `src/index.py`; Test `tests/test_preprocess_index.py`

**Interfaces:**
- Produces:

### Task 5: Encoders

**Files:** Create `src/encoders.py`; Test `tests/test_encoders.py`

**Interfaces:**
- Produces: `class Encoder(Protocol)`: `name: str`, `metric: str` ("ip"|"hamming"), `encode(images: list[Image.Image]) -> np.ndarray`. Implementations: `PHashEncoder(hash_size=8)` (`imagehash.phash`, returns uint8 `(n, hash_size**2/8)` packed bits, metric hamming); `ClipEncoder(arch, pretrained, device)` (open_clip `create_model_and_transforms`, image features L2-normalized float32, metric ip); `Dinov2Encoder(timm_name, image_size, device)` (timm `create_model(pretrained=True, num_classes=0)`, transforms from `timm.data.resolve_data_config` with input size `image_size`, CLS/pooled features L2-normalized float32). `get_encoder(name: str, cfg: dict) -> Encoder` for `clip|dinov2|phash`; unknown → `ValueError`. `resolve_device(spec: str) -> str` ("auto" → "cuda" if `torch.cuda.is_available()` and the device's compute capability is supported by the wheel (try a tiny tensor op, fall back on error), else "cpu"). Models are put in eval mode under `torch.inference_mode()`.

### Task 6: COCO subset selection and download

**Files:** Create `src/data.py`, `scripts/01_download.py`; Test `tests/test_data.py`

**Interfaces:**
- Produces:
  - `load_coco_instances(path: Path) -> list[dict]` — records `{"image_id": int, "file_name": str, "url": str (coco_url), "categories": sorted list[int]}`, only images with ≥1 annotation.
  - `select_subset(records: list[dict], n: int, seed: int) -> list[dict]` — deterministic `random.Random(seed).sample` on records sorted by image_id; n > len → all.
  - `download_images(records, dest: Path, fetch: Callable[[str], bytes]) -> dict` — writes `dest/file_name`; existing non-empty file skipped (no fetch); exceptions from fetch are caught, logged, counted; returns `{"downloaded": int, "skipped": int, "failed": list[int]}`; partial writes go to `*.part` then rename.

  - Script: extracts `instances_train2017.json` / `instances_val2017.json` from `data/annotations_trainval2017.zip` if not present, selects `data.gallery_size` train and `data.semantic_queries` val records, downloads via `requests` (timeout 30 s, 8 threads), writes manifests.

### Task 8: Evaluation

**Files:** Create `src/evaluate.py`, `scripts/05_evaluate.py`; Test `tests/test_evaluate.py`

**Interfaces:**
- Consumes: `SearchEngine.search`, metrics, trec writers, edits, manifests.
- Produces:
  - `evaluate_semantic(engine, queries: list[dict], gallery: list[dict], image_root: Path, representation: str, cfg) -> tuple[dict, list[dict]]` — per query: search with k = `search.eval_depth`, gains via `semantic_gains`, `ndcg_at_k(...,10)`, AP with rel = gain ≥ `eval.semantic_binary_threshold` and n_relevant counted over the whole gallery. Summary `{"task","representation","n_queries","n_skipped","ndcg@10","map","embed_ms","search_ms","rerank_ms"}` (latencies = medians). Per-query rows `{"qid","ap","ndcg@10"}`.
  - `evaluate_similar(engine, gallery, image_root, representation, cfg, n: int) -> tuple[dict, list[dict]]` — first n gallery records after `select_subset(gallery, n, seed)`, `assign_edits(n)`, query = `apply_edit(original)`, target = original id. Summary has `recall@1`, `recall@10`, `mrr` overall plus `recall@1_<edit>`, `recall@10_<edit>`, `mrr_<edit>` for each edit type, plus latencies. Per-query rows `{"qid","edit","rr","recall@1","recall@10"}`.
  - Both also write TREC runs `results/runs/<task>_<rep>.run` and qrels `results/runs/<task>.qrels` (semantic grade = round(3·gain), similar grade 1 for target).
  - `scripts/05_evaluate.py [--representations clip dinov2 phash] [--tasks semantic similar]` — cross table (every representation × both tasks), appends/overwrites rows in `results/summary.csv` (one row per task×representation, union of columns), per-query CSVs `results/per_query/<task>_<rep>.csv` sorted by AP/RR ascending (hard queries first).
